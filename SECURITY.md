# Seguridad


## Criterio común de mantenimiento y reportes

No publicar claves de firma, tokens, bases reales, respaldos ni datos personales en incidencias, capturas o archivos de ejemplo. Si un reporte requiere material sensible, no adjuntarlo a un issue público; coordinar un canal privado verificado con el propietario. No se inventa un correo de soporte ni se promete un plazo de respuesta.

No se declara auditoría completa ni garantía de seguridad. Ver [CRITERIOS.md](CRITERIOS.md) y [REVISION_PUBLICACION.md](REVISION_PUBLICACION.md). Una comprobación sin hallazgos no identifica todas las vulnerabilidades ni todos los datos privados. Un archivo ignorado puede seguir en Git si ya estaba versionado. Ante una credencial real expuesta, revocar/rotar y evaluar historial, artefactos y copias.

Los formatos de distribución conservan su alcance de pruebas documentado. Estas adiciones no reconstruyen APK, PDF o ZIP históricos ni cambian las versiones instaladas. Las claves privadas de firma deben conservarse separadamente para futuras actualizaciones compatibles.
